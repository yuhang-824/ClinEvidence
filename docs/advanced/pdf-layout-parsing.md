# PDF 双栏、规则表格与表单解析

本页供知识库管理员使用，说明本地 PDF 解析的适用范围与失败处理。已有文件的解析结果不会因更新代码自动变化，需要从原 PDF 重新解析。

## 选择解析方式

- 文字型 PDF：禁用 OCR 时使用文字坐标排序，保留常规单栏、双栏、规则表格和显式字段行。
- RapidOCR：文字页复用文字层；含图片、旋转文字或无法解码文字的页面整页 OCR，再按坐标组织结果。表单 Widget 的字段值同时读取，不依赖其是否出现在正文流中。
- MinerU、PP-Structure 等专用入口继续保留；复杂版式可选择已经部署的专用解析服务。

RapidOCR 使用本地模型推理，首次运行可能需要下载模型；医院离线部署前应预先准备模型文件并验证可用性。项目没有在本次修改中新增线上解析调用。

## 查看与重新解析

在知识库文件详情查看解析后的 Markdown。双栏正文按栏阅读，规则表格显示为 Markdown 表格；显式标签与同一行字段值保持关联。需要检查解析内容与原 PDF 一致后，再执行原有切片入库流程。

解析完成后在文件详情进入“清洗与审核”。左侧可切换原始解析与源文件，右侧修改清洗稿；保存修订后审核最新版本，再执行切片入库。版本列表保留历史内容、编辑人和审核时间。未保存修改不能审核，历史版本只读，版本冲突时撤销未保存修改并重新加载后再处理。

上传流程停在待审核稿，旧客户端的自动入库选项不会跳过审核。已有文件可点击“生成清洗稿”，从现存 Markdown 开始；若需要第一阶段的版面修复，必须从 PDF 重新解析。旧索引在新稿重新入库前继续服务旧内容，审核稿不会直接替换检索片段。医助的全文打开和关键词查找使用最近成功入库的版本。

重新解析和审核均不等于向量索引已经更新；入库任务的最终状态仍需在任务列表确认。

## 混合材料切片与来源

“清洗与审核”页使用混合材料策略：保存清洗稿后点击“预览切片”，检查片段和来源，再审核并点击“切片入库”。目标长度默认 512，范围为 64–4096，使用中英文近似 token 计数。完整字段组、推荐意见、表格行和单句可以超过目标长度，并显示核验提示；超过存储上限的结构块会明确拒绝，需要在清洗稿中人工分段。预览不调用嵌入模型，不写入索引；入库使用相同版本和长度参数。编辑内容或调整长度会使预览失效，后台执行时也会拒绝已过期的预览版本。

Markdown 标题作为章节上下文附加到片段。裸数字行不推断为标题，避免把剂量、时长当作章节；需要章节上下文时，在清洗稿中补充 `#` 标记。Markdown 表格按完整行切分并重复表名、表头；HTML 表格保留为完整单元。显式冒号字段及其续行保持关联，推荐标签后的连续条件和跨空行正文保持完整。中英文普通正文按预算组合，长段落优先按句切分，不自动翻译、改写术语或纠正剂量。

预览卡片和已入库片段卡片显示结构类型、内容版本、章节、审核稿行号及可确认的 PDF 页码。“查看来源段落”分别展示该版本中的章节、表头和正文。来源请求校验片段归属及期望版本；重新入库后旧卡片失效时提示刷新，不能将新版本原文显示为旧片段来源。检索结果的 metadata 同时携带来源信息，支持后续引用展示。

PDF 页码来自解析时保存的页边界，只用于定位整页，不提供文字坐标高亮。正文修订版本保留审核稿字符和行位置，暂不继承 PDF 页码，避免修改后错误定位。历史片段没有来源信息，使用混合材料重新入库后才具备版本追溯。General、QA、Book、Laws、Semantic、Separator 继续保留，知识库既有默认策略与索引不会自动切换。

## 修复不完整的片段

在“清洗与审核”中点击“预览切片”后，点击“修复切片”。选择问题片段，可查看前后各一段上下文，使用“与上一片段合并”“与下一片段合并”，或在正文中点击后使用“在光标处拆分”。拆分位置两侧必须都有文字。请在完整句子、表格行或字段组之间选点；人工操作仍需核对语义完整性。

“保存切分修订”保存新的待审核版本，正文不变，PDF 页码保留。保存失败时界面保留调整，可重试；“放弃调整”回到原预览。保存成功后自动重新预览，再点击“审核通过”和“切片入库”。人工边界保存在该文档版本中，重新打开仍生效，从其他索引入口操作也遵守该方案；目标长度不会移动人工切点。

如果片段中的文字本身识别错误，使用“定位清洗稿”对照源文件修改正文；有未保存边界时先确认放弃。正文修改需“保存修订”，旧边界与不可靠页码随之清除，再重新预览、审核和入库。如果仅想重新自动切分，使用“恢复自动切分”，确认后生成新的待审核版本，再调整目标长度预览。旧索引在新版本入库前继续使用。

冒号正文结合上下文判断，不单凭冒号生成表单片段；逐行空行的未完句继续连接。切片质量需要逐段复核，文字覆盖完整不代表语义完整。人工切片的来源仍回指保存的清洗稿，表格后续行补充可识别的表名与表头；不会自动补写缺失原文。

## 支持范围与限制

支持常规单/双栏、完整网格表、列对齐明确的三线表、显式冒号标签字段和 PDF Widget 原始字段值。完整网格表保留空单元格；三线表按列对齐和续行组织，首列缺失等歧义仍需对照原文核验。解析不自动纠正术语、数值或单位。

遇到不完整纵线、跨列识别框或无法确定列关系的规则表格时，解析明确失败，提示更换版面解析器。该检查不是任意布局的完整性证明；倾斜扫描、手写、复杂合并单元格、无明确标签的表单仍需专用解析和人工核验。OCR 可能丢失英文空格或识别错字。

当前返回格式仍是 Markdown；区域坐标用于解析过程，尚未形成供前端引用高亮使用的持久化区域索引。结构保护依赖解析稿的标题、表格和字段标记；无标签、合并单元格关系丢失或 OCR 错字需要先人工修订。中英文检索效果还取决于所部署的嵌入与重排模型，本阶段不提供跨语言召回质量保证。

## 清洗与质量提示

本地 PDF 在知识库解析时保留页边界，清洗规则仅删除多页重复且符合完整刊名及年月卷期格式的文字、明确格式的页码，并整理行尾空格与连续空行。连续普通中文行在满足保守条件时合并；数字、单位、字段、列表、表格及英文连字符不参与自动拼接。清洗记录保留处理前后文本与页内行号。

无页边界的解析结果不自动删除重复页眉页脚。空白、文字稀少或文字量显著下降的页面（疑似漏栏）、无法解码字符和不一致表格列数会生成核验提示；提示不能证明无漏栏、无漏页或医学内容正确。审核者需要对照原 PDF 检查这些项目。人工修订保留为新版本，旧版本内容不覆盖。

原始 Markdown 对象和 PDF 保留在 MinIO；内容版本、审核及成功入库时间保存在 PostgreSQL。部署需要先运行 Compose 的 storage-migrator 升级知识 Schema，再启动 API/worker。查看沿用知识库读取权限，生成、修订和审核要求管理权限；文件处理中拒绝编辑，最新稿未经审核时索引执行器拒绝入库。

实现定位：`backend/package/yuxi/knowledge/parser/pdf_layout.py` 与同目录的 `rapid_ocr.py`。
