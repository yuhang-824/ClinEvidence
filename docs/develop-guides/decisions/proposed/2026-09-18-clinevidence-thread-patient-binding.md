# 会话与患者绑定关系

状态：proposed
类型：architecture
Owner：backend/package/yuxi/services/conversation_service.py（会话绑定）、患者通道工具契约（M6 实施时注册）；分工见提案第 9 条

## 问题

本记录面向 ClinEvidence 开发者与面试评审，承接[阶段计划](../../clinevidence-roadmap.md) M2 患者业务模型，回答一个会话内出现多名患者材料时的回答归属问题：医生在同一对话中上传两名患者的病历后提问，系统如何保证检索、回答与引用对应正确患者。

现有会话（Conversation）没有患者概念，文件上传进入知识库且不区分患者。仅依赖提示词区分患者是概率性约束：模型分不清跨患者代词指代，长对话后生成环节可能把 A 患者细节写入 B 患者回答。仅靠前端限制会话患者数属于呈现层约束；按[开发约定](../../../../AGENTS.md)，前端守卫、prompt 与 schema omission 不是授权边界。

阶段计划已有三处相关约束：M5"每条通道及融合结果都约束患者/就诊/快照"、M6"跨患者/快照/伪造引用负向测试失败"、M7"切患者、摘要与缓存均隔离"。本记录把这三处约束收敛为一个会话模型决策，供 M2 实施时遵循。

非目标：不改变 EMR 对接与正式病历回写范围；不实现多患者对比功能；不约束结构化数据（检验数值、医嘱、诊断编码）的查询通道。

## 提案

### 会话模型

1. 会话持有"当前患者"引用（patient_id，可空）。患者会话创建时指定；为空时患者通道不可用，仅知识通道可回答。
2. 病历在上传时归属患者：导入批次必须绑定 patient 与 visit，来源片段与不可变快照继承该归属。没有患者归属的病历文件不得进入患者通道。
3. 同一会话出现第二个患者的材料时，系统不静默接受：提示"检测到新患者"，要求开新会话或显式切换当前患者。切换是带确认的重动作，切换后新快照生效，旧患者材料不再进入后续患者通道检索。
4. 多患者对比是二期显式功能（独立会话模式、明确选择对比对象、引用强制标注患者身份），通过独立提案引入，不是默认行为的隐式推论。

### 检索与生成的作用域

5. 患者通道检索的患者/就诊/快照作用域由服务端从会话绑定的"当前患者"解析；模型传入的患者标识不参与作用域计算，工具层忽略或拒绝不一致的患者参数。
6. 每轮回答的患者证据引用携带患者标识与快照版本；引用验证要求引用可回溯到当前患者已发布快照的来源片段。
7. 摘要、记忆与缓存按患者隔离：切换患者后，旧患者的摘要事件与缓存不得进入新患者的模型输入。
8. 知识通道（指南、文献、院内规范）无患者属性，不受会话患者绑定影响；两通道融合时，患者证据与知识证据分别标注来源通道。

### 事实 Owner 分工

9. 会话绑定关系与上传归属约束由患者业务模型（M2）拥有；患者通道工具的作用域解析与引用验证由工具契约（M6）拥有；摘要与缓存的跨患者隔离由上下文压缩链路（M7）拥有。提示词只描述行为，不承担隔离责任。

## 替代方案

| 方案 | 收益与代价 | 选择 |
|---|---|---|
| 定死一个会话只能一个患者且永不切换 | 心智最简单、演示清晰；只约束入口，不防生成串扰，堵死对比场景 | 不采用为唯一机制，其默认行为并入主方案 |
| 自由多患者会话，依赖提示词区分 | 不需要新增绑定关系；约束概率性、不可验收，跨患者泄漏不可防 | 不采用 |
| 仅前端强制患者选择 | 实现小；API 直调与工具调用绕过呈现层，属伪安全 | 不采用为安全边界 |
| 会话绑定当前患者 + 服务端作用域 + 负向验收 | 需要新增绑定关系、归属字段与作用域解析；可验收，为对比功能留落脚点 | 采用 |

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 患者检索不越界 | 作用域由模型参数决定 | 患者通道工具契约 | 真实 HTTP 会话绑定患者后检索，回读结果全部属于当前患者已发布快照 | 模型传入其他患者标识，检索仍被约束或明确拒绝 | Not run |
| 跨患者材料不静默混合 | 上传即混入患者通道 | 导入批次归属约束 | 同会话上传第二患者文件，回读提示与文件归属状态 | 未确认切换时，患者通道检索不到第二患者片段 | Not run |
| 引用可回溯患者 | 引用无患者身份 | 引用验证 | 回读引用记录的患者标识与快照版本字段 | 伪造引用或跨患者引用被判定失败 | Not run |
| 切换患者后不泄漏 | 摘要与缓存跨患者 | 上下文压缩链路 | 切换后读取新模型输入，不含旧患者摘要与片段 | 旧患者内容出现在新患者输入即为失败 | Not run |

实施按[测试规范](../../testing-guidelines.md)运行对应 unit、真实 HTTP integration 与 E2E；实现完成后本记录移入 `implemented/` 并改写为当前事实，回填实际命令与结果。

## 风险

- 会话绑定与上传归属扩展现有会话、文件和任务流程，演示操作步骤变长；验收覆盖"换患者"显式动作。
- 服务端作用域解析与现有工具参数 schema 存在调整成本，M6 契约需先于工具实现定稿。
- 摘要与缓存的患者隔离跨越既有 checkpoint 机制，M7 验证成本最高；失败时先缩小到"切会话不切患者"的严格模式。
- 默认单患者行为可能被评审认为限制效率；代价已在本记录接受，多患者对比走二期提案，不修改默认行为。
