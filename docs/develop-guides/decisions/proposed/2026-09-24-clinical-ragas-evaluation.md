# 患者问答 RAGAS 评估

状态：proposed  
类型：feature
Owner：backend/package/yuxi/services/clinical_ragas_service.py

## 问题

现有知识库评估只执行知识库检索及独立答案生成，不能衡量患者绑定 Agent 在病例、知识库共同参与时的实际回答质量。用户需要上传人工指定的测试集、选择评判模型，运行真实患者问答后查看逐题和汇总 RAGAS 指标。

## 提案

在患者库提供独立评估页面。导入测试题及可选元数据、患者映射；逐题校验患者可见性和已发布快照。后台任务为每题创建独立患者绑定对话，沿普通 AgentRun 链路获取最终回答和同 Run 的工具证据，再使用选定评判模型及向量模型计算 RAGAS 的上下文精确度、召回率、忠实度和回答相关性。每题错误及不可评分原因单独保存，汇总只统计真实完成的评分；按病例、指南和综合范围分组显示覆盖率。原有知识库评估保留。

现有 100 题中 50 道病例题、50 道指南题、没有显式综合题，且参考答案待临床复核。页面如实提示覆盖和复核状态，不把工程评分当作临床质量结论。

## 替代方案

- 直接改写知识库评估：会破坏现有知识库测试语义，无法绑定患者。
- 单独调用检索器和回答模型：不能测到真实 Agent 的工具选择与患者绑定。
- 仅做浏览器内批量运行：刷新后丢失进度，无法形成可追溯的 Run/证据关系。

## 风险

评估运行会产生 AgentRun、模型调用和包含脱敏病例内容的持久结果；必须由资源 Owner 控制读取和执行。模型失效、证据缺失、快照缺失均应记录为不可评分，不得补造满分或零分。先以解析、评分参数和状态投影单测验证；再用真实 PostgreSQL/HTTP/worker 与页面验证入口、权限、持久进度和终态。
