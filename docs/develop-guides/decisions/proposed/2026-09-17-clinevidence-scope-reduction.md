# ClinEvidence 循证医助依赖精简提案

状态：proposed
类型：simplification
Owner：docker-compose.yml

## 问题

读者是 ClinEvidence 的开发者；本页是依赖取舍与分阶段删除提案。目标是围绕循证医助及配套病历质控整理可移除能力，降低运行资源与维护成本。前置知识是现有 API、worker、知识库和 Agent 分工。第一批精简已实施，事实与验证见[本地 PDF 范围决策](../implemented/2026-09-17-clinevidence-local-pdf-scope.md)；单 Agent 部分见[已实施决策](../implemented/2026-09-17-clinevidence-single-agent.md)，本提案继续拥有其余后续批次，医疗业务闭环尚未验证。

范围沿用单 Agent、患者资料、指南证据检索、带引用回答与规则质控。知识图谱、多 Agent 协作、开放联网研究、任意代码执行不属于目标功能。模型接入和离线解析方案尚未确定，因此不能以“暂时未用”为理由删除模型、OCR 或文档解析基础能力。

当前启动契约保留本地文档知识库与评估；聊天实现还装配文件系统、Skills、摘要和可选子 Agent 中间件。删除容器、Python 包、前端页面是三个不同动作，需要沿真实调用链一起处理。

## 提案

### 保留的产品闭环

保留并围绕业务完善：登录与权限、模型连接配置、患者资料上传与查看、指南和质控规则管理、离线解析与索引、单 Agent 对话、来源文件及页码定位、质控结果与评分解释、历史记录、运行状态和评测。患者纵向档案、规则评分和引用准确性属于后续实现与验证目标，不能把平台已有通用页面等同于已完成的医疗功能。

基础拓扑先保留 Vue、FastAPI、worker、PostgreSQL、Redis、Milvus、etcd、MinIO。PostgreSQL 保存业务与 checkpoint；Redis/ARQ 支撑排队和异步任务；Milvus 与当前 etcd、MinIO 依赖一并保留。单 Agent 仍需要任务状态、取消、失败恢复和访问控制。

### 可移除能力与依赖

下表保留分批取舍；第一批的完成范围由已实施决策拥有，其余项仍为候选。运行时事实以 [Compose](https://github.com/yuhang-824/ClinEvidence/blob/main/docker-compose.yml)、[后端依赖](https://github.com/yuhang-824/ClinEvidence/blob/main/backend/package/pyproject.toml) 和 [前端依赖](https://github.com/yuhang-824/ClinEvidence/blob/main/web/package.json) 为准。

| 能力 | 处理顺序 | 依赖与删除边界 | 前置或保留项 |
|---|---|---|---|
| 知识图谱、图谱增强检索与展示 | 第一批移除 | `graph`/Neo4j 服务、`neo4j`、`networkx`、图谱路由与任务、图谱前端及 `@antv/g6` | 检查知识库导入/删除的图谱副作用、能力发现、启动和相关契约测试；保留普通向量检索 |
| 开放网页搜索与通用深度研究 | 第一批移除 | 搜索工具与预设、`langchain-tavily`；`tavily-python` 经锁文件确认后处理 | 离线指南检索继续可用；业务回答不能仍引用被删除工具 |
| MySQL 报表技能 | 第一批移除 | `mysql-reporter` 技能及其 `pymysql` 依赖 | 保留 PostgreSQL 业务存储；同步处理内置技能安装与测试 |
| Dify、Notion 等外部知识库接入 | 第一批收窄 | 外部类型入口、连接器、工厂注册与配置 | 保留本地知识库；先盘点是否有现存外部库记录，不能让历史记录变成不可解释的错误 |
| 多 Agent 委派与通用 Agent 管理 | 委派已移除，独立配置保留 | 子 Agent 预设、委派工具、中间件、配置和页面 | 保留单 Agent 的 LangGraph/LangChain、Run/FIFO/取消机制；`deepagents` 仍有其他消费者 |
| 定时 Agent 任务 | 第二批移除 | 调度页面、接口、服务、worker 注册；候选依赖 `croniter` | 队列重试、lease/heartbeat 等运行维护任务必须保留 |
| MCP 服务器管理 | 第二批移除 | 管理入口、启动初始化、工具发现、`langchain-mcp-adapters` | 医助工具用现有内部接口显式注册；`mcp` 是否仍为传递依赖以重新解析锁文件为准 |
| 通用沙盒与代码执行 | 第三批替换后移除 | sandbox provisioner、运行沙盒、`agent-sandbox`；provisioner 独有 Docker/Kubernetes SDK | 先把必要的附件、证据访问和摘要卸载文件操作改为受权限控制的服务；严禁改成宿主机任意执行 |
| 思维导图和通用统计面板 | 第二批按页面裁剪 | `markmap-lib`、`markmap-view`；`echarts` 只在所有消费者移除后处理 | 引用原文/PDF 查看保留；质控统计可能复用图表。`d3` 需核对构建和锁文件，不能因图谱消失就推定可删 |
| Langfuse 外部追踪 | 暂缓 | `langfuse` 已与聊天、反馈和 Run 链接接合 | 先保留本地审计、耗时、token、错误与证据记录，再决定是否移除外部追踪集成 |

### 暂时保留或无需启动

`openai`、`langchain-openai` 及其他模型适配依赖待聊天、Embedding、Rerank 三类接口验证后再裁剪；模型名称相似不等于协议相同。`langsmith`、`deepagents` 等还可能被框架直接或传递依赖，必须依据真实导入和锁文件结果决定。

保留 PDF、DOCX、表格解析与 OCR 的可用链路，包括当前 `docling-slim`、`pypdf`、`pypdfium2`、`rapidocr`、`onnxruntime`、图像处理等候选实现。先用实际文本型、扫描型和表格材料对比解析结果、页码与引用定位，再选一种主路径并删除冗余实现。前端 `pdfjs-dist` 用于来源阅读，不属于图谱依赖。

MinerU、PaddleX 在 Compose 中属于按 profile 启用的解析服务；未启动时删除其配置不会释放运行内存。先不启用，待 OCR 验证后决定是否从发行配置移除。镜像中的 LibreOffice、FFmpeg、Node/npm、Git 也需按预览、解析和工具实际消费者裁剪；依赖包大小不能直接等同于常驻内存收益。

Neo4j 是明确可以消除的常驻服务成本。沙盒运行实例按使用产生，收益取决于实际运行状态。WSL 文件缓存另有内存回收机制，移除这些功能不能保证 Vmmem 立刻下降同等数值。

### 执行顺序与完成条件

1. 固定基线：记录服务、模型配置状态、索引和数据目录；使用合成病例建立上传、检索、来源查看、对话和权限的回归样例。未接模型时明确记录缺口。
2. 删除第一批能力：先图谱，再搜索/报表技能和外部连接器；每项同时处理后端装配、前端入口、依赖声明与锁文件。用无 Neo4j 环境验证启动、导入、检索和文件删除；已有数据保留，数据卷清理单独处理。
3. 确认基座：接通聊天、Embedding、Rerank，并验证指南与病例离线入库。此阶段通过后，才能据证据裁剪模型和解析依赖。
4. 收窄到单医助：移除委派、定时任务、MCP 管理和无关页面。验证并发请求仍按约定排队，失败可恢复，历史结果可读。
5. 解耦沙盒并缩小镜像：必要文件操作由受控服务接管后再移除 provisioner 和相关依赖。分别对比空闲内存、实际请求峰值、镜像大小和构建时间。

## 替代方案

| 方案 | 收益与代价 | 选择 |
|---|---|---|
| 保留全平台，仅调整菜单 | 改动小；启动依赖与维护面仍存在 | 不采用为最终形态 |
| 收窄能力，分批删除已有装配 | 复用持久化、检索和运行机制；需要跨层回归 | 采用 |
| 替换存储为单库、重写 Agent | 可能进一步减少服务；增加检索、数据迁移和运行语义风险 | 当前不采用；先取得真实资源瓶颈证据 |
| 立即删除所有非医疗命名模块 | 文件少；会破坏共享解析、权限和聊天能力 | 不采用 |

## 验收标准

第一批删除的证据见[已实施决策](../implemented/2026-09-17-clinevidence-local-pdf-scope.md)；下表其余证据仍待后续实施。实现阶段须运行根工程契约、相关 unit、真实 HTTP/worker 回归及前端 lint/build/页面验证；不得用移除旧测试代替验证保留能力。

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 图谱及外部导入已移除 | 启动、API、工具残留 | Compose、routers、知识库工厂 | 已实施决策中的直接证据 | 恢复已移除入口使范围测试失败 | Passed |
| 普通聊天仍依赖共享 Agent 与文件系统 | 单 Agent 被误当成无需 deepagents/沙盒 | `agents/buildin/chatbot/graph.py`、`agents/backends` | 检查中间件、backend 创建及 Skills 同步 | 实现后缺失必要文件操作须显式报错，不能返回空证据成功 | Inspected |
| 无图谱部署可完成知识库主链路 | 注册、导入或删除残留图谱副作用 | `server/routers`、知识库服务、Compose | 无 Neo4j 运行真实上传→索引→检索→文件删除并读取状态 | 注入残留 Neo4j 调用，测试必须失败 | Passed |
| 医助回答可定位来源且遵守权限 | 虚假引用、跨用户读取 | 医助工具、文件 repository、前端来源查看 | 合成病例端到端验证来源页、无证据回答和越权拒绝 | 不存在来源/其他用户文件不可作为有效证据 | Not run |
| 单 Agent 保留持久化和异步运行语义 | 删除调度时误删队列、恢复或 checkpoint | Run/request services、worker、PostgreSQL | 执行真实请求 FIFO、取消、worker 重启与最终状态回读 | 重复投递或 worker 崩溃不能产生伪成功 | Not run |

旧能力不存在：实施对应批次后，相关 UI、API、工具注册、启动项和专有直接依赖均不存在，锁文件不存在无消费者的残留；传递依赖单独说明。旧数据的保留与清理不由“代码已删除”隐含授权。

重新引入条件：出现可验证的循证医助需求，并证明现有检索或受控服务无法满足，再通过独立提案引入图谱、联网工具或执行环境。

## 风险

架构、装配和验收边界遵循用户明确要求，保留本地文档知识库及评估。后续批次继续沿真实消费者裁剪，不能关闭整个契约检查。

删除连接器、调度和子 Agent 前应核查已有配置与持久记录；删除数据库列或历史记录不纳入依赖清理。模型和 OCR 尚未验证，所以目前不能宣称医疗回答、页码引用或质控评分已可用。评测功能保留，用于证明精简后仍满足业务目标。
