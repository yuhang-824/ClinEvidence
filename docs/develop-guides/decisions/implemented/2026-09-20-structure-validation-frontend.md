# 结构审核保存前置校验

状态：implemented
类型：bug-fix
Owner：web/src/components/knowledge/StructuredDocumentReview.vue

## 问题

在逐页结构审核勾选"不参与检索"但未填写"文块修订或排除说明"时保存，后端按契约拒绝并返回具体原因（如"排除文块必须说明原因，原文仍会保留"），但前端错误边界把 400 统一替换为"请求参数错误"（`web/src/apis/base.js` 的公开错误契约，防止服务端任意响应上下文进入前端消息与日志），用户不知道该改什么，审核入库流程被阻塞。

## 决策

在拥有结构数据的编辑器组件内做与后端同规则的保存前校验：排除文块必须填说明、未排除文块不得为空（对应 `revise_structure` 与 `compose_structure`），不通过时直接在审核界面列出精确到"第 X 页文块 N"的问题清单，不发请求；校验规则注释标注与后端同步。审核通过动作在面板内先调用编辑器暴露的 `validate('approve')`（整页核验勾选、含表格/图示/排除内容的页必须填核验说明，对应 `require_structure_review`），同样给出具体到页的提示。不改动 `base.js` 的错误脱敏契约。

## 替代方案

在 `base.js` 对 400 透传字符串 detail：违背该文件"不信任服务端响应内容"的既有安全契约（api_boundary 测试明确要求 400 的任意 detail 不得进入前端消息），不采用。仅在保存 API 失败后展示后端 detail：仍是请求后才知道错在哪，且需突破同一契约，不采用。只校验排除说明一条：空正文文块、审核页说明等同类规则同样会被 400 挡住且无提示，一次覆盖保存与审核两条链路的高频规则。

## 后果

用户在保存/审核前即看到精确到文块和页的中文提示，流程不再被无意义文案阻塞；规则在后端与前端各有一份，修改契约时必须同步（已注释标注）。未覆盖的后端规则（如修订大小上限、来源页保护）仍走服务端拒绝，文案保持通用。编辑文块会清空本页核验勾选的既有行为不变，审核前需重新勾选。

- `docker compose exec -T web pnpm run test:unit`：339 passed、0 failed。新增两项：编辑器 `保存前校验指出缺说明或空文块；审核校验列出需说明的页`（覆盖排除缺说明、空正文组合拦截与 approve 范围规则）；面板 `审核通过前置校验拦截未核验结构并显示具体原因，通过后放行`（有未通过校验时点击审核通过不发请求且渲染具体原因，清空问题后放行——独立审查指出面板接线缺负向测试后补充）。

- 真实页面验证（Docker 全链路）：验证账号登录 → 新建知识库 → 上传合成 PDF `verify_structure.pdf` → 解析完成（待入库）→ 打开文件详情"清洗与审核" → 勾选文块 1"不参与检索"不填说明点击保存，页面提示"第 1 页文块 1 已勾选「不参与检索」，请填写文块修订或排除说明"（替代原"请求参数错误"）→ 填写说明后保存成功（"结构修订与逐页核验已保存"），截图存档。验证后已删除该知识库与暂存文件。

## 未解决

`base.js` 对其余后端校验（无前端镜像的规则，如修订大小上限）仍显示通用文案；这些规则触发频率低且多为保护性约束，维持脱敏契约优先。
