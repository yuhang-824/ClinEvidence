# MinerU 图示使用已配置视觉模型生成审核草稿

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/ocr_service.py

## 问题

MinerU 能提取正文和表格，但 NCCN 等指南的流程图常只留下图片说明或占位文本。条件、箭头和分支没有进入结构稿，逐页审核只能从原图手工补录，检索也不能按路径召回。

## 决策

知识库使用 MinerU Official 解析 PDF 时，只有标为图示的块调用视觉模型。模型优先使用独立的系统 `pdf_vision_model` 配置，未设置时依次使用知识库的 `llm_model_spec` 和系统默认对话模型；没有模型时，含图示的解析明确失败。模型读取原 PDF 中的图示裁剪和整页上下文，只返回节点原文、箭头方向、条件、脚注和不确定项组成的 JSON。解析边界验证节点、连线与长度，再由确定性代码转为 `relationship` 文块检索文本；结构 JSON、模型标识和提示版本随审核稿保存。MinerU 的正文、表格、原始图注和坐标保留。图示识别失败时留下不可入库的占位文本与页级问题；识别成功也始终要求人工对照原图核验。

## 替代方案

让模型直接输出医学摘要：容易丢失分支条件、箭头与来源。把整页交给模型重新解析正文和表格：会重复 MinerU 已提取内容，造成冲突与较高成本。只保存 JSON 图而不生成正文：现有切片和检索只消费文块文本，图示不会进入索引。直接修改全站 `default_model` 会同时改变普通对话；独立视觉配置让 PDF 图示使用图片模型而不改动普通对话。

## 后果

新增的视觉处理只影响之后经 MinerU Official 解析的 PDF；已有文档需从原件重新解析。每个候选图示产生一次模型调用，增加解析时间与模型费用。解析任务完成时在审核稿中保留模型原始回复、结束原因和用量，即使 JSON 结构解析失败也可人工回看；连续两次失败后停止本次剩余视觉调用，避免对同一系统性问题继续付费。模型把 `<think>` 推理段与最终 JSON 放在同一正文时，只解析推理段之后的 JSON，同时保留完整原始回复。长达 1200 字的图中节点原文允许保留；无效的可选定位坐标清空并列为待核对项，不丢弃其余节点与箭头。关系文块仍作为完整结构单元切片，页级核验和图示说明要求不变；模型错误、非流程图和不确定项在审核页显式可见，不能作为机器核验结论。

## 验证

源码检查：`ocr_service.py` 仅在 MinerU 图示块存在时装配视觉链路；`flowchart_vision.py` 从 PDF 渲染图示，校验模型 JSON 并生成路径文本；`structure.py` 的占位文块审核门槛阻止失败结果入库。已用实际 NCCN 宫颈癌解析稿中保存的 M3 回复定位 `<think>`、长节点文字和退化坐标三个失败原因，并从保存的回复恢复三张流程图。该稿的 44 个图片块经原 PDF 核对后，28 个重复页眉标识从检索稿排除，14 个生成待审核的流程图结构，2 个非流程图示意图保留人工核对。API 容器 Python 语法检查、Web lint 与 build、文档 build 及 `git diff --check` 已通过；自动化测试未执行，因为本次请求未要求测试。
