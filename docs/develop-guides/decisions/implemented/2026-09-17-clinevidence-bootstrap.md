# ClinEvidence 项目定位与品牌边界

状态：implemented
类型：process
Owner：README.md

## 问题

秋招演示需要区分 Yuxi 提供的通用能力与医疗业务的个人贡献。输入源码来自不带 Git 历史的目录，配置版本号不能证明上游 commit，需求文档中的指标也不能视为实测结果。

## 决策

产品名称使用 ClinEvidence，目标仓库为 yuhang-824/ClinEvidence。默认品牌 YAML、Web 标题与主要展示入口采用新名称；README 与专属路线图描述当前状态和逐阶段验收。保留 Yuxi 的 MIT 许可证、内部 Python 包、CLI、环境变量与持久化标识。医疗功能按阶段开发，尚未形成运行或临床完成主张。

源码导入接续目标仓库初始提交，不重写已有历史。Shell 文件在 Git 中具有执行位，文本检出使用 LF，以支持跨平台复现。

## 替代方案

全量替换 yuxi 标识会扩大到 Python 导入、数据库、对象路径、CLI 与迁移，纯品牌需求不需要承担这些兼容风险。只改仓库名无法改变实际应用展示。选择现有品牌入口与必要的界面文案调整；历史技术资料保留上游语境并提供本项目启动入口。

## 后果

已有本地品牌覆盖文件仍优先于默认模板，部署者按品牌文档更新自有配置。项目保留基座既有通用能力；单 Agent、患者快照与医疗质控是路线图中的后续范围。首次上传包含完整继承源码，需要把源码基座与新增贡献分开介绍。

## 验证

工程契约检查、检查器单测、前端 lint、构建、文档构建及相关回归已执行。命令、结果、独立审查修复和未验证范围见[初始化验证记录](../../clinevidence-bootstrap-validation.md)。本机 WSL Docker 容器运行已验证；项目配置与服务尚未初始化，后端与正常业务链路未验证；登录页仅验证前端标题与后端不可达错误状态。未新增运行 guard。品牌期望值显式更新并经审查，不在 CI 自动生成。
