# 文档清洗与审核入库

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/document_review_service.py

## 问题

解析 Markdown 直接入库，缺少保留原始文本、清洗解释、人工修订和审核版本的边界。

## 决策

在 PostgreSQL 保存文件的不可变内容版本、清洗报告及审核人和时间。解析完成生成待审核稿；本地 PDF 保留页边界供重复页眉页脚判断。清洗仅处理确定的格式噪声，数值、单位、否定词、表格内容保持不变。文件详情提供原始文本、清洗稿、原 PDF 对照及历史版本。审核通过最新版本后，worker 才能切片入库；版本冲突和处理中编辑明确拒绝。已有索引继续服务其旧内容，草稿不修改已发布片段，重新索引发布审核版本。

## 替代方案

直接覆盖 MinIO Markdown 无法恢复原始解析；将审核状态放入可编辑 processing_params 会允许绕过。独立版本表与文件行锁提供持久化事实和并发边界，不新增外部服务。

## 后果

质量提示为启发式检查，不证明 OCR 完整或医学正确。无页界的外部解析结果不自动删除重复段落。复杂错栏和表格仍需人工核验；本阶段不改变分块算法或实现引用坐标高亮。新增知识 Schema 版本需迁移后重启 API/worker。

医助 open/find 读取最近成功入库版本；新草稿和仅审核未入库内容不改变发布全文。没有版本记录的旧 indexed/done 文件继续读取原 Markdown。原始对象与修订记录在文件删除时由原有对象清理和数据库外键级联删除。
